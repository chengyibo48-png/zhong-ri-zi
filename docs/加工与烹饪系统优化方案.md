# 加工与烹饪系统深度优化思路

加工与烹饪可以承担两类作用：**把农牧产物转化为更高价值的商品**，以及**为玩家提供探索、经营和冒险所需的料理**。系统设计可以围绕一条循环展开：

**获取食材 → 判断新鲜度与用途 → 选择加工设备或烹饪方式 → 管理时间、配方和火候 → 得到成品 → 销售、食用、赠送或继续加工。**

核心是让玩家在“马上出售原料”和“花时间加工提高价值”之间做选择，同时让烹饪和加工在操作方式、产物用途上各有特点。

## 一、系统定位与边界

建议把加工和烹饪设计成相连、但规则不同的两个部分：

- **加工**侧重批量、周期和计划：放入材料，等待设备处理，收取成品。
- **烹饪**侧重即时决策和使用：选择食材、执行操作，得到可以食用、赠送或销售的料理。

两者都消耗原料和时间，但各自提供不同价值。加工适合稳定经营，烹饪适合即时补给、订单和配方探索。

## 二、加工设备体系

设备不只应该是不同外观的容器，还应各自处理不同类型的原料，并拥有不同的时间、容量、品质和维护特征。

| 设备 | 主要用途 | 玩法特点 |
|---|---|---|
| 酿酒桶 | 水果、谷物等发酵为酒或饮品 | 周期较长，适合高价值、季节性原料 |
| 磨盘 | 谷物、豆类等磨成粉或基础加工品 | 速度较快，属于常用的中间加工设备 |
| 腌菜缸 | 蔬菜、鱼类等腌制保存 | 延长保质期，可通过香料或盐调整成品 |
| 榨油机 | 油料作物、坚果等提取食用油 | 将一部分原料转为基础烹饪材料 |
| 烘干机 | 水果、蔬菜、香草、肉类等脱水 | 降低重量或延长保存时间，适合处理过剩原料 |
| 奶酪槽或发酵架 | 奶类、乳制品进行发酵 | 周期较长，可发展品质与成熟度 |
| 蜜罐或糖浆锅 | 蜂蜜、果汁等加工 | 可作为高品质食品和烹饪辅料 |

### 1. 设备属性

每台设备可以有一组易于理解的属性：

- **加工时间**：决定生产周期。
- **单批容量**：决定每次能处理多少原料。
- **可加工类别**：限制材料和产物类型。
- **品质影响**：设备状态、材料品质或操作方式是否影响成品。
- **耐久与维护**：设备是否需要维修、清洁或更换耗材。
- **升级方向**：提升容量、缩短时间、改善品质或增加配方。

设备属性应该明确显示在界面里。玩家放入材料前就能知道预计耗时、预计产出数量和成品用途。

### 2. 加工流程

一次加工可以包含：

1. 选择设备。
2. 放入原料和可选辅料。
3. 查看预计产出与完成时间。
4. 等待设备处理。
5. 收取成品。

常规加工尽量不用每一步都要求玩家确认。复杂配方、稀有材料或品质追求可以增加选择；普通批量生产则应支持快速操作。

### 3. 多阶段加工

部分产品可以经过多道工序，例如谷物磨粉后用于烘焙，水果酿造后再陈酿。多阶段制作能形成生产链，但要控制步骤长度：

- 基础商品最好一两步即可完成。
- 高价值商品可以通过更多工序提高价值。
- 每一步都要有清楚的收益，例如保质期延长、售价提高或解锁用途。

避免为了制作普通物品而必须连续查看和操作多个设备。

## 三、固定配方与自由研发配方

### 1. 固定配方

固定配方保证玩家有可靠的制作方式，适合任务、基础料理和常规加工品。配方内容可以包括：

- 所需材料及数量。
- 设备或厨具要求。
- 加工时间。
- 预计品质范围。
- 成品用途。
- 可替代食材或可选辅料。

解锁方式可以是教程、商店、任务、节日、NPC 教授或探索发现。配方本身要能查看，不应要求玩家完全依靠外部记忆。

### 2. 自由研发

自由研发适合提供实验和发现感，但不宜让玩家必须盲试大量组合。可以采用“有限规则下的尝试”：

- 食材有类别和风味标签，例如甜、酸、香、鲜、辛。
- 配方槽位有作用，例如主料、辅料、调味料、香草。
- 玩家选择材料后，可查看大致风味预览。
- 成品可能获得已知配方、变体配方或失败结果。
- 成功实验会记录在配方册中，方便重复制作。

探索结果可以包括：

- 发现新配方。
- 解锁某种风味变化。
- 让已知配方获得新的食材替换方式。
- 获得成就、NPC 评价或订单机会。

失败最好也有部分回报，例如得到可食用的普通料理、保留部分材料，或记录“此组合不适合发酵”，而不是简单消耗全部稀有材料却一无所获。

### 3. 配方变体

同一基础配方可以通过食材替换、季节原料或辅料产生变体。变体可以改变：

- 口味与外观。
- 回复属性或增益效果。
- 品质上限。
- 保质期。
- NPC 喜好或订单适配。

变体应容易识别和记录，避免配方列表因微小差异膨胀得难以管理。

## 四、烹饪操作玩法

烹饪可以比加工更有即时参与感，但操作难度应控制在短而清晰的范围内。

### 1. 食材搭配

玩家先选择主食材，再选择辅料和调味品。每种食材可以带有明确标签，例如：

- 甜、酸、苦、咸、鲜、辛。
- 清爽、浓郁、温热、清凉。
- 蔬菜、谷物、肉类、乳制品、鱼类、香草。

搭配结果可以影响料理风味、恢复效果和适用场景。系统应通过文字或图标说明组合倾向，例如“偏清淡，适合恢复体力”或“香气浓郁，适合送给喜爱辛香料理的角色”。

### 2. 火候控制

火候可以采用短时操作，例如：

- 加热过程中观察温度或进度。
- 在适当区间加入、翻面或起锅。
- 操作成功提高品质，偏差只降低品质或增加耗时。

建议设置宽容的成功区间，避免玩家必须精确计时。熟练度、厨具升级或自动烹饪功能可以降低操作难度。

### 3. 多种操作模式

可以让玩家选择适合自己的烹饪方式：

- **快速制作**：使用固定配方，一步完成，结果稳定。
- **手动烹饪**：参与火候操作，有机会提高品质。
- **批量制作**：适合制作日常料理，减少重复点击。
- **自动烹饪**：后期通过升级或设施解锁，牺牲一部分品质上限换取便利。

操作玩法应是额外的参与感，不应成为获取基础食物或推进任务的强制门槛。

## 五、成品属性与用途

### 1. 品质

成品可以沿用普通、优质、上品、珍品等品质档位。影响因素包括：

- 原材料品质。
- 材料新鲜度。
- 配方熟练程度。
- 设备等级或状态。
- 烹饪火候。
- 季节和环境条件。
- 是否使用适配辅料。

品质差异应当可见且有价值，但基础品质的产品也要有实用用途，避免玩家觉得只有最高品质才值得制作。

### 2. 成品属性

不同成品可以提供不同用途：

- **体力回复**：用于劳作或冒险。
- **健康恢复**：用于恢复生命、疾病或疲劳状态。
- **特殊增益**：提升采集、钓鱼、移动、抗寒、抗热或社交效果。
- **经营用途**：满足订单、赠礼、节庆或收藏。
- **加工用途**：作为后续配方的中间材料。

增益效果需要清晰说明持续时间、叠加规则和适用情境。多种增益可以选择替换、延长或有限叠加，避免大量料理同时使用后让数值失控。

### 3. 保质期与保存方式

保质期可以影响成品是否新鲜、是否降低售价或效果。不同成品可以有不同保存特征：

- 新鲜料理：效果好，但保存时间较短。
- 腌制品、干货和发酵品：保存时间长，方便囤积或远距离交易。
- 高品质成品：可设置更高价值，但保质期不必天然更长。
- 冷藏设施：延长保质期，或减缓新鲜度下降。

过期后可以分级处理，例如品质下降、售价减少，严重时无法食用。尽量避免让库存物品在短时间内全部腐坏，造成玩家损失感。

## 六、食材新鲜度机制

### 1. 新鲜度如何变化

食材新鲜度可以由收获或获得时间开始计算，并受存放环境影响：

- 常温下逐渐下降。
- 冷藏或特殊容器减慢下降。
- 加工可以重置、延长或转化保质期。
- 新鲜食材用于烹饪时可能提升品质或效果。
- 部分配方更适合使用成熟度较高的原料。

新鲜度建议用几个清楚的等级表示，例如“新鲜、尚可、临近变质、变质”，同时在详情中显示剩余时间或预计变化。

### 2. 新鲜度如何参与配方

新鲜度可以影响料理质量和市场价值，但应避免让玩家为了保鲜而被迫频繁上线。建议：

- 初期采用较宽松的保质期。
- 设置仓库、地窖、冰箱等保存设施。
- 可加工的食材提供稳定的保鲜出口。
- 过期损失分阶段发生，给玩家处理机会。
- 订单或任务明确说明是否接受非新鲜材料。

### 3. 成熟度和新鲜度的区别

水果、奶制品、肉类等不同食材可能需要分别表示新鲜度和成熟度：

- **新鲜度**表示是否变质。
- **成熟度**表示是否达到最佳使用阶段。

某些酒、奶酪或腌制品需要时间成熟；这时“放久了”可能提升品质，而不是变坏。界面要清楚区分熟成时间和腐败时间。

## 七、季节限定加工规则

季节可以影响原料供给、制作配方、加工效率和市场需求。

- 某些食材只在特定季节容易获得。
- 季节限定配方可以来自节日、当地传统或特殊订单。
- 某些发酵和晾晒过程可受温度、湿度影响。
- 季节性需求可以改变部分商品的售价或订单数量。
- 大棚、地窖、冷藏和特殊设备可延长材料供应或稳定加工环境。

季节限定更适合作为额外机会，而不是错过就无法补回的关键内容。可以通过次年复现、旅行商人、储存原料或配方传承等方式提供回归机会。

## 八、熟练度与配方解锁

烹饪和加工熟练度可以作为长期成长，但不宜只体现为“数值变高”。

熟练后可以解锁：

- 更稳定地做出高品质成品。
- 发现额外配方或配方变体。
- 降低操作失误概率。
- 提高设备批量处理能力。
- 识别食材搭配效果。
- 解锁特殊订单或经营许可。

熟练度可以按类别分别积累，例如烘焙、发酵、腌制、饮品、热菜。类别不宜过多，避免技能树拆得太碎。

## 九、与其他系统的联动

加工和烹饪能够把种植、养殖、采集、钓鱼和交易连接起来：

- 作物提供蔬菜、水果、谷物、油料和香草。
- 动物提供蛋、奶、肉、蜂蜜等食材。
- 采集提供香料、蘑菇和野生果物。
- 加工把季节过剩产物转成耐储存商品。
- 料理支持体力管理、冒险和角色互动。
- 订单、商店和节庆提供阶段性需求。
- 副产物可以回到农场，例如残渣做饲料或堆肥。

联动应让玩家有多种获取路径。比如缺少鸡蛋时，玩家可以购买或选择替代配方，而不是被迫先建立完整的养鸡系统。

## 十、界面与生产规划

为了降低管理成本，配方和设备界面可以提供：

- **配方册**：按食物类型、设备、材料和已解锁状态筛选。
- **库存检查**：显示可制作数量、缺少材料和替代选项。
- **加工队列**：展示正在运行的设备、剩余时间和待收取产物。
- **成品预览**：显示预计品质、效果、保质期和售价范围。
- **批量制作**：选择制作数量，一次排入队列。
- **保鲜提示**：标记即将变质的食材，建议制作哪些配方。
- **订单提示**：指出当前成品能否满足订单及交付数量。

批量制作和设备队列尤其重要。随着设备增加，玩家应该能集中管理生产，而不是逐个打开设备查状态。

## 十一、需要避免的问题

- **配方过多但缺乏差异**：配方要对应不同用途、风味、效果或市场需求。
- **食材库存容易腐坏**：保质期应宽松，并提供保存和加工出口。
- **加工链太长**：复杂工序只适合高价值商品，基础料理要容易制作。
- **自由研发依赖盲试**：使用食材标签、配方线索和失败记录帮助玩家学习。
- **火候操作太苛刻**：操作应提高表现，而不是决定玩家能否获得基本料理。
- **高品质变成唯一目标**：普通品质也应能完成订单、补充体力或赚取基础收益。
- **设备泛化**：每种设备要有明确用途，避免所有机器只是同一套输入输出逻辑。

## 十二、推荐的实施顺序

后续实际落地时，可以按下面的顺序分阶段构建：

1. **基础烹饪与加工**：食材、固定配方、设备、加工时间和成品收取。
2. **品质与用途**：食材品质、成品品质、体力回复、售价和订单用途。
3. **设备差异与队列**：增加加工类别、批量处理和生产队列。
4. **新鲜度与保存**：食材保鲜、冷藏设施、腌制和烘干等保存方式。
5. **烹饪操作与配方研发**：火候玩法、食材标签、配方发现和变体。
6. **季节与熟练度**：季节限定原料、市场需求、制作熟练度和高级配方。
7. **系统联动**：将种植、畜牧、探索、订单和加工产业链连接起来。

第一阶段先让“原料—配方—设备或烹饪—成品—用途”跑通。之后再增加新鲜度、配方研发和季节变化，系统会更容易理解，也更容易调整数值。
